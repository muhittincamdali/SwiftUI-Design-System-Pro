DesignSystemPro — это Swift-пакет для приложений на SwiftUI, которым нужен единый внешний вид без
разработки с нуля. В нём есть дизайн-токены (цвета, типографика, отступы, рамки, тени, анимация), движок
тем со светлой, тёмной, готовыми и фирменными темами и около 40 представлений-компонентов, построенных на
токенах: кнопки, текстовые поля, переключатели, карточки, бейджи, аватары, всплывающие уведомления
(toasts) и скелетоны загрузки. Каждый компонент подбирает цвета под светлый или тёмный режим, а текст,
оформленный токенами типографики, следует Dynamic Type.

## Основные возможности

- **Светлый и тёмный режим** — у каждого цветового токена есть светлое, тёмное и высококонтрастное
  значение, и компоненты берут нужное из окружения.
- **Dynamic Type** — `dsTypography(_:)` масштабирует стили текста по размеру шрифта, выбранному
  пользователем.
- **Темы для ваших собственных представлений** — `ThemeManager` следует системе или применяет готовую
  тему либо тему, созданную из фирменных цветов; читайте её через `@Environment(\.dsTheme)`.
- **Проверка контраста** — `ColorContrastUtility` вычисляет коэффициенты контраста WCAG; тесты проверяют
  основной текст и подписи залитых кнопок на соответствие WCAG AA в обеих цветовых схемах.
- **Проверенная отрисовка** — тест рисует каждую группу компонентов в светлом и тёмном режиме и сравнивает
  её с сохранёнными эталонными отпечатками, поэтому изменение цвета или раскладки роняет CI.
- **Пять платформ** — iOS, macOS, tvOS, watchOS и visionOS в одном пакете без зависимостей во время
  выполнения.

## Быстрый старт

**1. Добавьте пакет**

В Xcode выберите **File › Add Package Dependencies…** и введите адрес репозитория:

```text
https://github.com/muhittincamdali/SwiftUI-Design-System-Pro.git
```

Оставьте **Dependency Rule** в значении **Up to Next Major Version**, начиная с 2.0.0, и нажмите
**Add Package**. В следующем окне выберите таргет приложения рядом с **DesignSystemPro** и снова
нажмите **Add Package**.

**2. Импортируйте модуль**

Добавьте эту строку в начало Swift-файла, в котором используете компоненты:

```swift
import DesignSystemPro
```

**3. Используйте**

Замените содержимое `ContentView.swift` в новом проекте приложения на SwiftUI кодом ниже и запустите
приложение (**Product › Run**, ⌘R). Вы увидите заголовок, зелёный бейдж «Ready», переключатель и кнопку
во всю ширину, которая переключает его.

```swift
import DesignSystemPro
import SwiftUI

struct ContentView: View {
    @State private var notificationsOn = true

    var body: some View {
        VStack(spacing: SpacingTokens.Content.comfortable) {
            Text("Hello, DesignSystemPro")
                .dsTypography(TypographyTokens.Heading.h2)

            DSStatusBadge("Ready", variant: .success)

            DSToggle(isOn: $notificationsOn, label: "Notifications")

            DSButton("Continue", isFullWidth: true) {
                notificationsOn.toggle()
            }
        }
        .padding(SpacingTokens.Layout.screenEdge)
    }
}
```

Тот же файл есть в примере приложения:
[Examples/DesignSystemProDemo/Sources/ContentView.swift](Examples/DesignSystemProDemo/Sources/ContentView.swift).

## Установка

### Swift Package Manager

В Xcode выберите **File › Add Package Dependencies…** и введите адрес репозитория:

```text
https://github.com/muhittincamdali/SwiftUI-Design-System-Pro.git
```

Или добавьте его в `dependencies` вашего `Package.swift`:

```swift
dependencies: [
    .package(url: "https://github.com/muhittincamdali/SwiftUI-Design-System-Pro.git", from: "2.0.0")
],
targets: [
    .target(name: "YourApp", dependencies: [
        .product(name: "DesignSystemPro", package: "SwiftUI-Design-System-Pro")
    ])
]
```

Версии до 2.0.0 содержат старый API 1.x, который этот README не описывает.

## Использование

### Подключите провайдер темы и слой уведомлений

Оберните корневое представление в `DSApp`. Он помещает активную тему в окружение и добавляет слой, который
показывает уведомления:

```swift
import DesignSystemPro
import SwiftUI

@main
struct MyApp: App {
    var body: some Scene {
        WindowGroup {
            DSApp { ContentView() }
        }
    }
}
```

### Соберите экран из компонентов

Компоненты принимают обычные значения и привязки (bindings); отступы и шрифты берутся из токенов. Вот
экран входа из примера приложения:

```swift
struct SignInView: View {
    @State private var email = ""
    @State private var isSubmitting = false

    var body: some View {
        VStack(spacing: SpacingTokens.Content.comfortable) {
            Text("Welcome back").dsTypography(TypographyTokens.Heading.h2)

            DSTextField("Email", text: $email, placeholder: "you@example.com")

            DSButton("Sign in", isFullWidth: true) {
                isSubmitting = true
                DSToastManager.shared.success("Signed in")
            }
            .loading(isSubmitting)

            HStack {
                DSAvatar(name: "Ada Lovelace", status: .online)
                DSStatusBadge("Verified", variant: .success)
            }
        }
        .padding(SpacingTokens.Layout.screenEdge)
        .frame(maxWidth: .infinity, maxHeight: .infinity)
        .dsBackgroundColor(ColorTokens.Background.primary)
    }
}
```

### Выберите тему

`ThemeManager` следует системной настройке светлого и тёмного режима, пока вы не зададите тему:

```swift
// Follow the system light/dark setting (the default) ...
DesignSystemPro.configure()

// ... or force a preset or a generated brand theme.
ThemeManager.shared.setTheme(PresetThemes.ocean)

let brand = BrandConfiguration(primaryColor: .purple, secondaryColor: .pink, borderRadius: 12)
ThemeManager.shared.setTheme(WhiteLabelConfiguration(brand: brand, appName: "Acme").darkTheme)
```

Ваши собственные представления читают активную тему через `@Environment(\.dsTheme)`. Встроенные
компоненты используют цветовые токены напрямую, и тема не меняет их оформление.

### Проверьте контраст

```swift
let ratio = ColorContrastUtility.contrastRatio(.white, Color(hex: "#2563EB")) // about 5.2
let passes = ColorContrastUtility.meetsWCAG_AA(.white, Color(hex: "#2563EB")) // true
```

Каждый фрагмент Swift-кода в этом README (кроме выдержки из `Package.swift`) компилируется и запускается
в [Tests/DesignSystemProTests/ReadmeExamples.swift](Tests/DesignSystemProTests/ReadmeExamples.swift).

## Архитектура

```text
Sources/DesignSystemPro
├── Tokens/      ColorTokens, TypographyTokens, SpacingTokens, BorderTokens, ShadowTokens, AnimationTokens
├── Theme/       DSTheme, ThemeManager, DSThemeProvider, presets, brand/white-label generation
├── Components/  Buttons, text input, selection, cards, badges, avatars, toasts, skeletons
└── DesignSystemPro.swift   configure() and DSApp
```

| Семейство      | Представления                                                                                                            |
| -------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Кнопки         | `DSButton` (6 вариантов, 5 размеров, иконки, состояние загрузки), `DSIconButton`, `DSButtonGroup`                        |
| Ввод текста    | `DSTextField` (состояния проверки, скрытый ввод), `DSTextArea`, `DSSearchField`, `DSOTPField`                            |
| Выбор          | `DSToggle`, `DSSwitch`, `DSCheckbox`, `DSCheckboxGroup`, `DSRadio`, `DSRadioGroup`                                       |
| Контент        | `DSCard`, `DSCardHeader`, `DSCardFooter`, `DSStatCard`, `DSMediaCard`, `DSListCard`, `DSCardListItem`                    |
| Бейджи         | `DSBadge`, `DSCounterBadge`, `DSDotBadge`, `DSStatusBadge`, `DSTag`                                                      |
| Аватары        | `DSAvatar` (изображение, инициалы или заглушка, точка статуса), `DSAvatarGroup`, `DSBorderedAvatar`, `DSAvatarWithBadge` |
| Обратная связь | `DSToastManager` с `DSToastContainer`/`DSToastView`, `DSSnackbar`                                                        |
| Загрузка       | `DSSkeleton` и скелетоны текста, аватара, карточки, списка, таблицы и профиля; `DSConditionalSkeleton`                   |

- Компоненты построены на токенах и не читают тему. Токены — простые типы-значения `Sendable`.
- `ThemeManager` и `DSToastManager` — классы `@MainActor` `@Observable` с общими экземплярами и
  публичными инициализаторами, поэтому их можно внедрять (`DSThemeProvider(themeManager:)`,
  `DSToastContainer(manager:)`) и тестировать.
- Тесты (`swift test`) написаны на Swift Testing и проверяют вычисления токенов, контраст, выбор темы,
  очередь и таймеры уведомлений, вспомогательные функции компонентов, фрагменты кода из документации,
  эталонные отпечатки каждой группы компонентов в светлом и тёмном режиме, а также представления,
  размещённые в AppKit, для провайдера темы, цвета переключателя и рамки фокуса поля OTP. CI запускает их
  и на симуляторе iOS.

## План развития

- Научить компоненты читать активную тему, чтобы готовые и фирменные темы меняли и их оформление.
- Поднять до уровня WCAG AA контраст инициалов аватаров на светлых цветах палитры и галочки флажка в
  тёмном режиме.

В июне 2026 года пакет был сведён к файлам-заглушкам; версия 2.0 восстанавливает прежние токены, движок
тем и компоненты, исправляет найденные по ходу ошибки и добавляет тесты. Компоненты из API 1.x
(оповещения, модальные окна, панель навигации, панель вкладок, графики) не возвращены. Идеи и сообщения
об ошибках приветствуются в виде [issue](https://github.com/muhittincamdali/SwiftUI-Design-System-Pro/issues).
