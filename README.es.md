DesignSystemPro es un paquete de Swift para apps SwiftUI que quieren un aspecto coherente sin construirlo
desde cero. Incluye tokens de diseño (colores, tipografía, espaciado, bordes, sombras y movimiento), un
motor de temas con temas claros, oscuros, predefinidos y de marca, y unas 40 vistas de componentes
construidas sobre los tokens: botones, campos de texto, interruptores, tarjetas, insignias, avatares,
avisos (toasts) y esqueletos de carga. Cada componente resuelve sus colores para el modo claro y el
oscuro, y el texto con estilos de los tokens tipográficos sigue Dynamic Type.

## Lo más destacado

- **Modo claro y oscuro**: cada token de color tiene un valor claro, uno oscuro y uno de alto contraste,
  y los componentes eligen el adecuado a partir del entorno.
- **Dynamic Type**: `dsTypography(_:)` escala los estilos de texto según el tamaño de texto que haya
  elegido el usuario.
- **Temas para tus propias vistas**: `ThemeManager` sigue al sistema o aplica un tema predefinido o uno
  generado a partir de los colores de tu marca; léelo con `@Environment(\.dsTheme)`.
- **Comprobación de contraste**: `ColorContrastUtility` calcula ratios de contraste WCAG; los tests
  comprueban el texto de cuerpo y las etiquetas de los botones rellenos contra WCAG AA en ambos esquemas
  de color.
- **Renderizado con tests**: un test dibuja cada grupo de componentes en modo claro y oscuro y lo compara
  con huellas de referencia guardadas, así que un cambio de color o de disposición hace fallar la CI.
- **Cinco plataformas**: iOS, macOS, tvOS, watchOS y visionOS desde un solo paquete sin dependencias en
  tiempo de ejecución.

## Inicio rápido

**1. Añade el paquete**

En Xcode, elige **File › Add Package Dependencies…** e introduce la URL del repositorio:

```text
https://github.com/muhittincamdali/SwiftUI-Design-System-Pro.git
```

Deja **Dependency Rule** en **Up to Next Major Version**, a partir de 2.0.0, y pulsa **Add Package**.
En la siguiente ventana, elige el target de tu app junto a **DesignSystemPro** y vuelve a pulsar
**Add Package**.

**2. Importa el módulo**

Añade esta línea al principio del archivo Swift en el que uses los componentes:

```swift
import DesignSystemPro
```

**3. Úsalo**

Sustituye el contenido de `ContentView.swift` de un proyecto nuevo de app SwiftUI por el código de abajo
y ejecuta la app (**Product › Run**, ⌘R). Verás un título, una insignia verde "Ready", un interruptor y
un botón de ancho completo que cambia el interruptor.

```swift
import DesignSystemPro
import SwiftUI

struct ContentView: View {
    @State private var notificationsOn = true

    var body: some View {
        VStack(spacing: SpacingTokens.Content.comfortable) {
            Text("Hello, DesignSystemPro")
                .dsTypography(TypographyTokens.Heading.h2)

            DSStatusBadge("Ready", variant: .success)

            DSToggle(isOn: $notificationsOn, label: "Notifications")

            DSButton("Continue", isFullWidth: true) {
                notificationsOn.toggle()
            }
        }
        .padding(SpacingTokens.Layout.screenEdge)
    }
}
```

El mismo archivo está en la app de ejemplo:
[Examples/DesignSystemProDemo/Sources/ContentView.swift](Examples/DesignSystemProDemo/Sources/ContentView.swift).

## Instalación

### Swift Package Manager

En Xcode, elige **File › Add Package Dependencies…** e introduce la URL del repositorio:

```text
https://github.com/muhittincamdali/SwiftUI-Design-System-Pro.git
```

O añádelo a las `dependencies` de tu `Package.swift`:

```swift
dependencies: [
    .package(url: "https://github.com/muhittincamdali/SwiftUI-Design-System-Pro.git", from: "2.0.0")
],
targets: [
    .target(name: "YourApp", dependencies: [
        .product(name: "DesignSystemPro", package: "SwiftUI-Design-System-Pro")
    ])
]
```

Las versiones anteriores a la 2.0.0 contienen la antigua API 1.x, que este README no describe.

## Uso

### Instala el proveedor de temas y la capa de avisos

Envuelve la vista raíz en `DSApp`. Pone el tema activo en el entorno y añade la capa que muestra los
avisos:

```swift
import DesignSystemPro
import SwiftUI

@main
struct MyApp: App {
    var body: some Scene {
        WindowGroup {
            DSApp { ContentView() }
        }
    }
}
```

### Construye una pantalla con componentes

Los componentes reciben valores y bindings normales; el espaciado y la tipografía salen de los tokens.
Esta es la pantalla de inicio de sesión de la app de ejemplo:

```swift
struct SignInView: View {
    @State private var email = ""
    @State private var isSubmitting = false

    var body: some View {
        VStack(spacing: SpacingTokens.Content.comfortable) {
            Text("Welcome back").dsTypography(TypographyTokens.Heading.h2)

            DSTextField("Email", text: $email, placeholder: "you@example.com")

            DSButton("Sign in", isFullWidth: true) {
                isSubmitting = true
                DSToastManager.shared.success("Signed in")
            }
            .loading(isSubmitting)

            HStack {
                DSAvatar(name: "Ada Lovelace", status: .online)
                DSStatusBadge("Verified", variant: .success)
            }
        }
        .padding(SpacingTokens.Layout.screenEdge)
        .frame(maxWidth: .infinity, maxHeight: .infinity)
        .dsBackgroundColor(ColorTokens.Background.primary)
    }
}
```

### Elige un tema

`ThemeManager` sigue el ajuste claro/oscuro del sistema hasta que fijas un tema:

```swift
// Follow the system light/dark setting (the default) ...
DesignSystemPro.configure()

// ... or force a preset or a generated brand theme.
ThemeManager.shared.setTheme(PresetThemes.ocean)

let brand = BrandConfiguration(primaryColor: .purple, secondaryColor: .pink, borderRadius: 12)
ThemeManager.shared.setTheme(WhiteLabelConfiguration(brand: brand, appName: "Acme").darkTheme)
```

Tus propias vistas leen el tema activo con `@Environment(\.dsTheme)`. Los componentes incluidos usan
directamente los tokens de color y el tema no cambia su estilo.

### Comprueba el contraste

```swift
let ratio = ColorContrastUtility.contrastRatio(.white, Color(hex: "#2563EB")) // about 5.2
let passes = ColorContrastUtility.meetsWCAG_AA(.white, Color(hex: "#2563EB")) // true
```

Cada fragmento de Swift de este README (salvo el extracto de `Package.swift`) se compila y se ejecuta en
[Tests/DesignSystemProTests/ReadmeExamples.swift](Tests/DesignSystemProTests/ReadmeExamples.swift).

## Arquitectura

```text
Sources/DesignSystemPro
├── Tokens/      ColorTokens, TypographyTokens, SpacingTokens, BorderTokens, ShadowTokens, AnimationTokens
├── Theme/       DSTheme, ThemeManager, DSThemeProvider, presets, brand/white-label generation
├── Components/  Buttons, text input, selection, cards, badges, avatars, toasts, skeletons
└── DesignSystemPro.swift   configure() and DSApp
```

| Familia          | Vistas                                                                                                               |
| ---------------- | -------------------------------------------------------------------------------------------------------------------- |
| Botones          | `DSButton` (6 variantes, 5 tamaños, iconos, estado de carga), `DSIconButton`, `DSButtonGroup`                        |
| Entrada de texto | `DSTextField` (estados de validación, entrada segura), `DSTextArea`, `DSSearchField`, `DSOTPField`                   |
| Selección        | `DSToggle`, `DSSwitch`, `DSCheckbox`, `DSCheckboxGroup`, `DSRadio`, `DSRadioGroup`                                   |
| Contenido        | `DSCard`, `DSCardHeader`, `DSCardFooter`, `DSStatCard`, `DSMediaCard`, `DSListCard`, `DSCardListItem`                |
| Insignias        | `DSBadge`, `DSCounterBadge`, `DSDotBadge`, `DSStatusBadge`, `DSTag`                                                  |
| Avatares         | `DSAvatar` (imagen, iniciales o marcador, punto de estado), `DSAvatarGroup`, `DSBorderedAvatar`, `DSAvatarWithBadge` |
| Respuesta        | `DSToastManager` con `DSToastContainer`/`DSToastView`, `DSSnackbar`                                                  |
| Carga            | `DSSkeleton` y esqueletos de texto, avatar, tarjeta, lista, tabla y perfil; `DSConditionalSkeleton`                  |

- Los componentes se construyen a partir de los tokens y no leen el tema. Los tokens son tipos de valor
  `Sendable` sencillos.
- `ThemeManager` y `DSToastManager` son clases `@MainActor` `@Observable` con instancias compartidas e
  inicializadores públicos, así que se pueden inyectar (`DSThemeProvider(themeManager:)`,
  `DSToastContainer(manager:)`) y probar.
- Los tests (`swift test`) usan Swift Testing: cálculos de tokens, contraste, resolución de temas, la
  cola y los temporizadores de avisos, funciones auxiliares de los componentes, los fragmentos de la
  documentación, huellas de referencia de cada grupo de componentes en modo claro y oscuro, y vistas
  alojadas en AppKit para el proveedor de temas, el color del interruptor y el anillo de foco del campo
  OTP. La CI también los ejecuta en un simulador de iOS.

## Hoja de ruta

- Hacer que los componentes lean el tema activo, para que los temas predefinidos y de marca también
  cambien su estilo.
- Subir a WCAG AA el contraste de las iniciales de los avatares sobre los colores claros de la paleta y
  el de la marca de la casilla en modo oscuro.

En junio de 2026 el paquete quedó reducido a archivos de relleno; la 2.0 recupera los tokens, el motor de
temas y los componentes anteriores, corrige los errores encontrados por el camino y añade los tests. Los
componentes de la API 1.x (alertas, modales, barra de navegación, barra de pestañas, gráficos) no se han
recuperado. Las ideas y los informes de errores son bienvenidos como
[issues](https://github.com/muhittincamdali/SwiftUI-Design-System-Pro/issues).
