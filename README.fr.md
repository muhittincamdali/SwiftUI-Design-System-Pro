DesignSystemPro est un paquet Swift pour les apps SwiftUI qui veulent une apparence cohérente sans tout
construire elles-mêmes. Il fournit des design tokens (couleurs, typographie, espacements, bordures,
ombres, animations), un moteur de thèmes avec des thèmes clairs, sombres, prédéfinis et de marque, et une
quarantaine de vues de composants construites sur ces tokens : boutons, champs de texte, interrupteurs,
cartes, badges, avatars, toasts et squelettes de chargement. Chaque composant choisit ses couleurs selon
le mode clair ou sombre, et le texte mis en forme avec les tokens typographiques suit Dynamic Type.

## Points forts

- **Mode clair et mode sombre** : chaque token de couleur a une valeur claire, une valeur sombre et une
  valeur à contraste élevé, et les composants prennent la bonne dans l’environnement.
- **Dynamic Type** : `dsTypography(_:)` adapte les styles de texte à la taille de texte choisie par
  l’utilisateur.
- **Des thèmes pour vos propres vues** : `ThemeManager` suit le système ou applique un thème prédéfini
  ou un thème généré à partir des couleurs de votre marque ; lisez-le avec `@Environment(\.dsTheme)`.
- **Vérification du contraste** : `ColorContrastUtility` calcule les rapports de contraste WCAG ; les
  tests vérifient le texte courant et les libellés des boutons pleins par rapport à WCAG AA dans les deux
  modes de couleur.
- **Rendu testé** : un test dessine chaque groupe de composants en mode clair et sombre et le compare à
  des empreintes de référence enregistrées ; un changement de couleur ou de mise en page fait donc échouer
  la CI.
- **Cinq plateformes** : iOS, macOS, tvOS, watchOS et visionOS avec un seul paquet, sans dépendance à
  l’exécution.

## Démarrage rapide

**1. Ajouter le paquet**

Dans Xcode, choisissez **File › Add Package Dependencies…** et saisissez l’URL du dépôt :

```text
https://github.com/muhittincamdali/SwiftUI-Design-System-Pro.git
```

Réglez **Dependency Rule** sur **Branch**, saisissez `main`, puis cliquez sur **Add Package**. Dans la
fenêtre suivante, choisissez la cible de votre app en face de **DesignSystemPro** et cliquez de nouveau
sur **Add Package**. (La version 2.0.0, la première avec cette API, n’a pas encore de tag ; une fois
qu’elle en aura un, choisissez plutôt **Up to Next Major Version**.)

**2. Importer le module**

Ajoutez cette ligne en haut du fichier Swift dans lequel vous utilisez les composants :

```swift
import DesignSystemPro
```

**3. L’utiliser**

Remplacez le contenu de `ContentView.swift` dans un nouveau projet d’app SwiftUI par le code ci-dessous,
puis lancez l’app (**Product › Run**, ⌘R). Vous voyez un titre, un badge vert « Ready », un interrupteur
et un bouton pleine largeur qui bascule l’interrupteur.

```swift
import DesignSystemPro
import SwiftUI

struct ContentView: View {
    @State private var notificationsOn = true

    var body: some View {
        VStack(spacing: SpacingTokens.Content.comfortable) {
            Text("Hello, DesignSystemPro")
                .dsTypography(TypographyTokens.Heading.h2)

            DSStatusBadge("Ready", variant: .success)

            DSToggle(isOn: $notificationsOn, label: "Notifications")

            DSButton("Continue", isFullWidth: true) {
                notificationsOn.toggle()
            }
        }
        .padding(SpacingTokens.Layout.screenEdge)
    }
}
```

Le même fichier se trouve dans l’app d’exemple :
[Examples/DesignSystemProDemo/Sources/ContentView.swift](Examples/DesignSystemProDemo/Sources/ContentView.swift).

## Installation

### Swift Package Manager

Dans Xcode, choisissez **File › Add Package Dependencies…** et saisissez l’URL du dépôt :

```text
https://github.com/muhittincamdali/SwiftUI-Design-System-Pro.git
```

Ou ajoutez-le aux `dependencies` de votre `Package.swift` :

```swift
dependencies: [
    .package(url: "https://github.com/muhittincamdali/SwiftUI-Design-System-Pro.git", branch: "main")
],
targets: [
    .target(name: "YourApp", dependencies: [
        .product(name: "DesignSystemPro", package: "SwiftUI-Design-System-Pro")
    ])
]
```

Le dernier tag, 1.0.0, contient l’ancienne API 1.x, que ce README ne décrit pas. Utilisez
`branch: "main"` jusqu’au tag 2.0.0, puis `from: "2.0.0"`.

## Utilisation

### Installer le fournisseur de thème et la couche des toasts

Enveloppez la vue racine dans `DSApp`. Elle place le thème actif dans l’environnement et ajoute la couche
qui affiche les toasts :

```swift
import DesignSystemPro
import SwiftUI

@main
struct MyApp: App {
    var body: some Scene {
        WindowGroup {
            DSApp { ContentView() }
        }
    }
}
```

### Construire un écran avec les composants

Les composants prennent des valeurs et des bindings ordinaires ; les espacements et la typographie
viennent des tokens. Voici l’écran de connexion de l’app d’exemple :

```swift
struct SignInView: View {
    @State private var email = ""
    @State private var isSubmitting = false

    var body: some View {
        VStack(spacing: SpacingTokens.Content.comfortable) {
            Text("Welcome back").dsTypography(TypographyTokens.Heading.h2)

            DSTextField("Email", text: $email, placeholder: "you@example.com")

            DSButton("Sign in", isFullWidth: true) {
                isSubmitting = true
                DSToastManager.shared.success("Signed in")
            }
            .loading(isSubmitting)

            HStack {
                DSAvatar(name: "Ada Lovelace", status: .online)
                DSStatusBadge("Verified", variant: .success)
            }
        }
        .padding(SpacingTokens.Layout.screenEdge)
        .frame(maxWidth: .infinity, maxHeight: .infinity)
        .dsBackgroundColor(ColorTokens.Background.primary)
    }
}
```

### Choisir un thème

`ThemeManager` suit le réglage clair/sombre du système tant que vous ne définissez pas de thème :

```swift
// Follow the system light/dark setting (the default) ...
DesignSystemPro.configure()

// ... or force a preset or a generated brand theme.
ThemeManager.shared.setTheme(PresetThemes.ocean)

let brand = BrandConfiguration(primaryColor: .purple, secondaryColor: .pink, borderRadius: 12)
ThemeManager.shared.setTheme(WhiteLabelConfiguration(brand: brand, appName: "Acme").darkTheme)
```

Vos propres vues lisent le thème actif avec `@Environment(\.dsTheme)`. Les composants fournis utilisent
directement les tokens de couleur et le thème ne modifie pas leur style.

### Vérifier le contraste

```swift
let ratio = ColorContrastUtility.contrastRatio(.white, Color(hex: "#2563EB")) // about 5.2
let passes = ColorContrastUtility.meetsWCAG_AA(.white, Color(hex: "#2563EB")) // true
```

[Tests/DesignSystemProTests/ReadmeExamples.swift](Tests/DesignSystemProTests/ReadmeExamples.swift).

## Architecture

```text
Sources/DesignSystemPro
├── Tokens/      ColorTokens, TypographyTokens, SpacingTokens, BorderTokens, ShadowTokens, AnimationTokens
├── Theme/       DSTheme, ThemeManager, DSThemeProvider, presets, brand/white-label generation
├── Components/  Buttons, text input, selection, cards, badges, avatars, toasts, skeletons
└── DesignSystemPro.swift   configure() and DSApp
```

| Famille         | Vues                                                                                                                    |
| --------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Boutons         | `DSButton` (6 variantes, 5 tailles, icônes, état de chargement), `DSIconButton`, `DSButtonGroup`                        |
| Saisie de texte | `DSTextField` (états de validation, saisie sécurisée), `DSTextArea`, `DSSearchField`, `DSOTPField`                      |
| Sélection       | `DSToggle`, `DSSwitch`, `DSCheckbox`, `DSCheckboxGroup`, `DSRadio`, `DSRadioGroup`                                      |
| Contenu         | `DSCard`, `DSCardHeader`, `DSCardFooter`, `DSStatCard`, `DSMediaCard`, `DSListCard`, `DSCardListItem`                   |
| Badges          | `DSBadge`, `DSCounterBadge`, `DSDotBadge`, `DSStatusBadge`, `DSTag`                                                     |
| Avatars         | `DSAvatar` (image, initiales ou espace réservé, point d’état), `DSAvatarGroup`, `DSBorderedAvatar`, `DSAvatarWithBadge` |
| Retours         | `DSToastManager` avec `DSToastContainer`/`DSToastView`, `DSSnackbar`                                                    |
| Chargement      | `DSSkeleton` et squelettes de texte, d’avatar, de carte, de liste, de tableau et de profil ; `DSConditionalSkeleton`    |

- Les composants sont construits à partir des tokens et ne lisent pas le thème. Les tokens sont de
  simples types valeur `Sendable`.
- `ThemeManager` et `DSToastManager` sont des classes `@MainActor` `@Observable` avec des instances
  partagées et des initialiseurs publics ; on peut donc les injecter (`DSThemeProvider(themeManager:)`,
  `DSToastContainer(manager:)`) et les tester.
- Les tests (`swift test`) utilisent Swift Testing : calculs des tokens, contraste, résolution des
  thèmes, file d’attente et minuteurs des toasts, fonctions utilitaires des composants, extraits de la
  documentation, empreintes de référence de chaque groupe de composants en mode clair et sombre, et vues
  hébergées dans AppKit pour le fournisseur de thème, la couleur de l’interrupteur et l’anneau de focus du
  champ OTP. La CI les exécute aussi sur un simulateur iOS.

## Feuille de route

- Taguer la 2.0.0 et publier les notes de version à partir de [CHANGELOG.md](CHANGELOG.md).
- Faire lire le thème actif aux composants, pour que les thèmes prédéfinis et de marque modifient aussi
  leur style.
- Porter au niveau WCAG AA le contraste des initiales des avatars sur les couleurs claires de la palette
  et celui de la coche des cases à cocher en mode sombre.

En juin 2026, le paquet avait été réduit à des fichiers provisoires ; la 2.0 restaure les tokens, le moteur de
thèmes et les composants précédents, corrige les bogues trouvés au passage et ajoute les tests. Les
composants de l’API 1.x (alertes, fenêtres modales, barre de navigation, barre d’onglets, graphiques)
n’ont pas été repris. Les idées et les rapports de bogues sont les bienvenus sous forme
d’[issues](https://github.com/muhittincamdali/SwiftUI-Design-System-Pro/issues).
