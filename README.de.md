DesignSystemPro ist ein Swift-Paket für SwiftUI-Apps, die ein einheitliches Erscheinungsbild wollen,
ohne es von Grund auf selbst zu bauen. Es enthält Design-Tokens (Farben, Typografie, Abstände, Rahmen,
Schatten, Animation), eine Theme-Engine mit hellen, dunklen, vordefinierten und Marken-Themes sowie rund
40 Komponenten-Views, die auf den Tokens aufbauen: Buttons, Textfelder, Schalter, Karten, Badges,
Avatare, Toasts und Skeleton-Platzhalter. Jede Komponente wählt ihre Farben passend zum hellen oder
dunklen Modus, und Text mit den Typografie-Tokens folgt Dynamic Type.

## Highlights

- **Heller und dunkler Modus** – jedes Farb-Token hat einen hellen, einen dunklen und einen
  kontrastreichen Wert, und die Komponenten wählen den passenden aus der Umgebung.
- **Dynamic Type** – `dsTypography(_:)` skaliert die Schriftstile mit der Textgröße, die der Nutzer
  eingestellt hat.
- **Themes für deine eigenen Views** – `ThemeManager` folgt dem System oder wendet ein vordefiniertes
  Theme oder ein aus deinen Markenfarben erzeugtes Theme an; du liest es mit `@Environment(\.dsTheme)`.
- **Kontrastprüfung** – `ColorContrastUtility` berechnet WCAG-Kontrastverhältnisse; die Tests prüfen
  Fließtext und die Beschriftung gefüllter Buttons in beiden Farbschemata gegen WCAG AA.
- **Getestetes Rendering** – ein Test zeichnet jede Komponentengruppe im hellen und dunklen Modus und
  vergleicht sie mit gespeicherten Referenz-Fingerabdrücken, sodass eine Farb- oder Layoutänderung die CI
  scheitern lässt.
- **Fünf Plattformen** – iOS, macOS, tvOS, watchOS und visionOS aus einem Paket ohne
  Laufzeitabhängigkeiten.

## Schnellstart

**1. Paket hinzufügen**

Wähle in Xcode **File › Add Package Dependencies…** und gib die Repository-URL ein:

```text
https://github.com/muhittincamdali/SwiftUI-Design-System-Pro.git
```

Lass **Dependency Rule** auf **Up to Next Major Version** ab 2.0.0 und klicke auf **Add Package**. Wähle im
nächsten Fenster neben **DesignSystemPro** dein App-Target aus und klicke noch einmal auf **Add Package**.

**2. Modul importieren**

Füge diese Zeile oben in der Swift-Datei ein, in der du die Komponenten verwendest:

```swift
import DesignSystemPro
```

**3. Verwenden**

Ersetze den Inhalt von `ContentView.swift` in einem neuen SwiftUI-App-Projekt durch den folgenden Code
und starte die App (**Product › Run**, ⌘R). Du siehst eine Überschrift, ein grünes „Ready“-Badge, einen
Schalter und einen Button über die volle Breite, der den Schalter umlegt.

```swift
import DesignSystemPro
import SwiftUI

struct ContentView: View {
    @State private var notificationsOn = true

    var body: some View {
        VStack(spacing: SpacingTokens.Content.comfortable) {
            Text("Hello, DesignSystemPro")
                .dsTypography(TypographyTokens.Heading.h2)

            DSStatusBadge("Ready", variant: .success)

            DSToggle(isOn: $notificationsOn, label: "Notifications")

            DSButton("Continue", isFullWidth: true) {
                notificationsOn.toggle()
            }
        }
        .padding(SpacingTokens.Layout.screenEdge)
    }
}
```

Dieselbe Datei liegt in der Beispiel-App:
[Examples/DesignSystemProDemo/Sources/ContentView.swift](Examples/DesignSystemProDemo/Sources/ContentView.swift).

## Installation

### Swift Package Manager

Wähle in Xcode **File › Add Package Dependencies…** und gib die Repository-URL ein:

```text
https://github.com/muhittincamdali/SwiftUI-Design-System-Pro.git
```

Oder füge es zu den `dependencies` in deiner `Package.swift` hinzu:

```swift
dependencies: [
    .package(url: "https://github.com/muhittincamdali/SwiftUI-Design-System-Pro.git", from: "2.0.0")
],
targets: [
    .target(name: "YourApp", dependencies: [
        .product(name: "DesignSystemPro", package: "SwiftUI-Design-System-Pro")
    ])
]
```

Versionen vor 2.0.0 enthalten die ältere 1.x-API, die diese README nicht beschreibt.

## Verwendung

### Theme-Provider und Toast-Overlay einbinden

Umschließe die Root-View mit `DSApp`. Es legt das aktive Theme in die Umgebung und fügt das Overlay
hinzu, das Toasts anzeigt:

```swift
import DesignSystemPro
import SwiftUI

@main
struct MyApp: App {
    var body: some Scene {
        WindowGroup {
            DSApp { ContentView() }
        }
    }
}
```

### Einen Screen aus Komponenten bauen

Komponenten nehmen einfache Werte und Bindings entgegen; Abstände und Schrift kommen aus den Tokens. Das
ist der Anmeldebildschirm der Beispiel-App:

```swift
struct SignInView: View {
    @State private var email = ""
    @State private var isSubmitting = false

    var body: some View {
        VStack(spacing: SpacingTokens.Content.comfortable) {
            Text("Welcome back").dsTypography(TypographyTokens.Heading.h2)

            DSTextField("Email", text: $email, placeholder: "you@example.com")

            DSButton("Sign in", isFullWidth: true) {
                isSubmitting = true
                DSToastManager.shared.success("Signed in")
            }
            .loading(isSubmitting)

            HStack {
                DSAvatar(name: "Ada Lovelace", status: .online)
                DSStatusBadge("Verified", variant: .success)
            }
        }
        .padding(SpacingTokens.Layout.screenEdge)
        .frame(maxWidth: .infinity, maxHeight: .infinity)
        .dsBackgroundColor(ColorTokens.Background.primary)
    }
}
```

### Ein Theme wählen

`ThemeManager` folgt der Hell-/Dunkel-Einstellung des Systems, bis du ein Theme setzt:

```swift
// Follow the system light/dark setting (the default) ...
DesignSystemPro.configure()

// ... or force a preset or a generated brand theme.
ThemeManager.shared.setTheme(PresetThemes.ocean)

let brand = BrandConfiguration(primaryColor: .purple, secondaryColor: .pink, borderRadius: 12)
ThemeManager.shared.setTheme(WhiteLabelConfiguration(brand: brand, appName: "Acme").darkTheme)
```

Deine eigenen Views lesen das aktive Theme mit `@Environment(\.dsTheme)`. Die mitgelieferten Komponenten
verwenden die Farb-Tokens direkt und werden vom Theme nicht umgestaltet.

### Kontrast prüfen

```swift
let ratio = ColorContrastUtility.contrastRatio(.white, Color(hex: "#2563EB")) // about 5.2
let passes = ColorContrastUtility.meetsWCAG_AA(.white, Color(hex: "#2563EB")) // true
```

Jedes Swift-Snippet in dieser README (außer dem Auszug aus `Package.swift`) wird von
[Tests/DesignSystemProTests/ReadmeExamples.swift](Tests/DesignSystemProTests/ReadmeExamples.swift)
kompiliert und ausgeführt.

## Architektur

```text
Sources/DesignSystemPro
├── Tokens/      ColorTokens, TypographyTokens, SpacingTokens, BorderTokens, ShadowTokens, AnimationTokens
├── Theme/       DSTheme, ThemeManager, DSThemeProvider, presets, brand/white-label generation
├── Components/  Buttons, text input, selection, cards, badges, avatars, toasts, skeletons
└── DesignSystemPro.swift   configure() and DSApp
```

| Familie     | Views                                                                                                                |
| ----------- | -------------------------------------------------------------------------------------------------------------------- |
| Buttons     | `DSButton` (6 Varianten, 5 Größen, Icons, Ladezustand), `DSIconButton`, `DSButtonGroup`                              |
| Texteingabe | `DSTextField` (Validierungszustände, sichere Eingabe), `DSTextArea`, `DSSearchField`, `DSOTPField`                   |
| Auswahl     | `DSToggle`, `DSSwitch`, `DSCheckbox`, `DSCheckboxGroup`, `DSRadio`, `DSRadioGroup`                                   |
| Inhalt      | `DSCard`, `DSCardHeader`, `DSCardFooter`, `DSStatCard`, `DSMediaCard`, `DSListCard`, `DSCardListItem`                |
| Badges      | `DSBadge`, `DSCounterBadge`, `DSDotBadge`, `DSStatusBadge`, `DSTag`                                                  |
| Avatare     | `DSAvatar` (Bild, Initialen oder Platzhalter, Statuspunkt), `DSAvatarGroup`, `DSBorderedAvatar`, `DSAvatarWithBadge` |
| Feedback    | `DSToastManager` mit `DSToastContainer`/`DSToastView`, `DSSnackbar`                                                  |
| Laden       | `DSSkeleton` und Skeletons für Text, Avatar, Karte, Liste, Tabelle und Profil; `DSConditionalSkeleton`               |

- Die Komponenten bauen auf den Tokens auf und lesen das Theme nicht. Tokens sind einfache
  `Sendable`-Werttypen.
- `ThemeManager` und `DSToastManager` sind `@MainActor`-`@Observable`-Klassen mit geteilten Instanzen
  und öffentlichen Initialisierern; sie lassen sich daher injizieren (`DSThemeProvider(themeManager:)`,
  `DSToastContainer(manager:)`) und testen.
- Die Tests (`swift test`) verwenden Swift Testing: Token-Berechnungen, Kontrast, Theme-Auflösung, die
  Toast-Warteschlange und ihre Timer, Hilfsfunktionen der Komponenten, die Snippets der Dokumentation,
  Referenz-Fingerabdrücke jeder Komponentengruppe im hellen und dunklen Modus und in AppKit gehostete
  Views für den Theme-Provider, die Schalterfarbe und den Fokusrahmen des OTP-Felds. Die CI führt sie
  auch auf einem iOS-Simulator aus.

## Roadmap

- Die Komponenten das aktive Theme lesen lassen, damit vordefinierte und Marken-Themes auch sie
  umgestalten.
- Den Kontrast der Avatar-Initialen auf den helleren Palettenfarben und des Häkchens der Checkbox im
  dunklen Modus auf WCAG AA anheben.

Im Juni 2026 wurde das Paket auf Platzhalterdateien reduziert; 2.0 stellt die früheren Tokens, die
Theme-Engine und die Komponenten wieder her, behebt die dabei gefundenen Fehler und ergänzt die Tests.
Komponenten aus der 1.x-API (Alerts, Modals, Navigationsleiste, Tab-Leiste, Diagramme) wurden nicht
zurückgeholt. Ideen und Fehlerberichte sind als
[Issues](https://github.com/muhittincamdali/SwiftUI-Design-System-Pro/issues) willkommen.
