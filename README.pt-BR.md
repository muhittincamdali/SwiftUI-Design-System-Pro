DesignSystemPro é um pacote Swift para apps SwiftUI que querem uma aparência consistente sem construí-la
do zero. Ele traz design tokens (cores, tipografia, espaçamento, bordas, sombras e animação), um
mecanismo de temas com temas claros, escuros, predefinidos e de marca, e cerca de 40 views de componentes
construídas sobre os tokens: botões, campos de texto, chaves, cartões, selos, avatares, toasts e
esqueletos de carregamento. Cada componente escolhe as cores para o modo claro ou escuro, e o texto
estilizado com os tokens de tipografia acompanha o Dynamic Type.

## Destaques

- **Modo claro e escuro**: cada token de cor tem um valor claro, um escuro e um de alto contraste, e os
  componentes pegam o certo a partir do ambiente.
- **Dynamic Type**: `dsTypography(_:)` ajusta os estilos de texto ao tamanho de texto escolhido pelo
  usuário.
- **Temas para as suas próprias views**: `ThemeManager` segue o sistema ou aplica um tema predefinido ou
  um tema gerado a partir das cores da sua marca; leia-o com `@Environment(\.dsTheme)`.
- **Verificação de contraste**: `ColorContrastUtility` calcula razões de contraste WCAG; os testes
  verificam o texto do corpo e os rótulos dos botões preenchidos contra o WCAG AA nos dois esquemas de cor.
- **Renderização testada**: um teste desenha cada grupo de componentes no modo claro e no escuro e
  compara com impressões digitais de referência salvas, então uma mudança de cor ou de layout faz a CI
  falhar.
- **Cinco plataformas**: iOS, macOS, tvOS, watchOS e visionOS em um único pacote, sem dependências em
  tempo de execução.

## Início rápido

**1. Adicione o pacote**

No Xcode, escolha **File › Add Package Dependencies…** e informe a URL do repositório:

```text
https://github.com/muhittincamdali/SwiftUI-Design-System-Pro.git
```

Mude **Dependency Rule** para **Branch**, digite `main` e clique em **Add Package**. Na janela seguinte,
escolha o target do seu app ao lado de **DesignSystemPro** e clique em **Add Package** de novo. (A 2.0.0,
primeira versão com esta API, ainda não tem tag; quando tiver, escolha **Up to Next Major Version**.)

**2. Importe o módulo**

Adicione esta linha no topo do arquivo Swift em que você usa os componentes:

```swift
import DesignSystemPro
```

**3. Use**

Substitua o conteúdo de `ContentView.swift` em um novo projeto de app SwiftUI pelo código abaixo e
execute o app (**Product › Run**, ⌘R). Você vê um título, um selo verde "Ready", uma chave e um botão de
largura total que liga e desliga a chave.

```swift
import DesignSystemPro
import SwiftUI

struct ContentView: View {
    @State private var notificationsOn = true

    var body: some View {
        VStack(spacing: SpacingTokens.Content.comfortable) {
            Text("Hello, DesignSystemPro")
                .dsTypography(TypographyTokens.Heading.h2)

            DSStatusBadge("Ready", variant: .success)

            DSToggle(isOn: $notificationsOn, label: "Notifications")

            DSButton("Continue", isFullWidth: true) {
                notificationsOn.toggle()
            }
        }
        .padding(SpacingTokens.Layout.screenEdge)
    }
}
```

O mesmo arquivo está no app de exemplo:
[Examples/DesignSystemProDemo/Sources/ContentView.swift](Examples/DesignSystemProDemo/Sources/ContentView.swift).

## Instalação

### Swift Package Manager

No Xcode, escolha **File › Add Package Dependencies…** e informe a URL do repositório:

```text
https://github.com/muhittincamdali/SwiftUI-Design-System-Pro.git
```

Ou adicione-o às `dependencies` do seu `Package.swift`:

```swift
dependencies: [
    .package(url: "https://github.com/muhittincamdali/SwiftUI-Design-System-Pro.git", branch: "main")
],
targets: [
    .target(name: "YourApp", dependencies: [
        .product(name: "DesignSystemPro", package: "SwiftUI-Design-System-Pro")
    ])
]
```

A tag mais recente, 1.0.0, tem a API 1.x antiga, que este README não descreve. Use `branch: "main"` até
a 2.0.0 receber a tag e, depois, `from: "2.0.0"`.

## Uso

### Instale o provedor de tema e a camada de toasts

Envolva a view raiz em `DSApp`. Ela coloca o tema ativo no ambiente e adiciona a camada que mostra os
toasts:

```swift
import DesignSystemPro
import SwiftUI

@main
struct MyApp: App {
    var body: some Scene {
        WindowGroup {
            DSApp { ContentView() }
        }
    }
}
```

### Monte uma tela com componentes

Os componentes recebem valores e bindings comuns; espaçamento e tipografia vêm dos tokens. Esta é a tela
de login do app de exemplo:

```swift
struct SignInView: View {
    @State private var email = ""
    @State private var isSubmitting = false

    var body: some View {
        VStack(spacing: SpacingTokens.Content.comfortable) {
            Text("Welcome back").dsTypography(TypographyTokens.Heading.h2)

            DSTextField("Email", text: $email, placeholder: "you@example.com")

            DSButton("Sign in", isFullWidth: true) {
                isSubmitting = true
                DSToastManager.shared.success("Signed in")
            }
            .loading(isSubmitting)

            HStack {
                DSAvatar(name: "Ada Lovelace", status: .online)
                DSStatusBadge("Verified", variant: .success)
            }
        }
        .padding(SpacingTokens.Layout.screenEdge)
        .frame(maxWidth: .infinity, maxHeight: .infinity)
        .dsBackgroundColor(ColorTokens.Background.primary)
    }
}
```

### Escolha um tema

`ThemeManager` segue a configuração clara/escura do sistema até você definir um tema:

```swift
// Follow the system light/dark setting (the default) ...
DesignSystemPro.configure()

// ... or force a preset or a generated brand theme.
ThemeManager.shared.setTheme(PresetThemes.ocean)

let brand = BrandConfiguration(primaryColor: .purple, secondaryColor: .pink, borderRadius: 12)
ThemeManager.shared.setTheme(WhiteLabelConfiguration(brand: brand, appName: "Acme").darkTheme)
```

As suas próprias views leem o tema ativo com `@Environment(\.dsTheme)`. Os componentes incluídos usam os
tokens de cor diretamente e não mudam de estilo com o tema.

### Verifique o contraste

```swift
let ratio = ColorContrastUtility.contrastRatio(.white, Color(hex: "#2563EB")) // about 5.2
let passes = ColorContrastUtility.meetsWCAG_AA(.white, Color(hex: "#2563EB")) // true
```

Cada trecho em Swift deste README (exceto o trecho de `Package.swift`) é compilado e executado por
[Tests/DesignSystemProTests/ReadmeExamples.swift](Tests/DesignSystemProTests/ReadmeExamples.swift).

## Arquitetura

```text
Sources/DesignSystemPro
├── Tokens/      ColorTokens, TypographyTokens, SpacingTokens, BorderTokens, ShadowTokens, AnimationTokens
├── Theme/       DSTheme, ThemeManager, DSThemeProvider, presets, brand/white-label generation
├── Components/  Buttons, text input, selection, cards, badges, avatars, toasts, skeletons
└── DesignSystemPro.swift   configure() and DSApp
```

| Família          | Views                                                                                                                |
| ---------------- | -------------------------------------------------------------------------------------------------------------------- |
| Botões           | `DSButton` (6 variantes, 5 tamanhos, ícones, estado de carregamento), `DSIconButton`, `DSButtonGroup`                |
| Entrada de texto | `DSTextField` (estados de validação, entrada segura), `DSTextArea`, `DSSearchField`, `DSOTPField`                    |
| Seleção          | `DSToggle`, `DSSwitch`, `DSCheckbox`, `DSCheckboxGroup`, `DSRadio`, `DSRadioGroup`                                   |
| Conteúdo         | `DSCard`, `DSCardHeader`, `DSCardFooter`, `DSStatCard`, `DSMediaCard`, `DSListCard`, `DSCardListItem`                |
| Selos            | `DSBadge`, `DSCounterBadge`, `DSDotBadge`, `DSStatusBadge`, `DSTag`                                                  |
| Avatares         | `DSAvatar` (imagem, iniciais ou marcador, ponto de status), `DSAvatarGroup`, `DSBorderedAvatar`, `DSAvatarWithBadge` |
| Feedback         | `DSToastManager` com `DSToastContainer`/`DSToastView`, `DSSnackbar`                                                  |
| Carregamento     | `DSSkeleton` e esqueletos de texto, avatar, cartão, lista, tabela e perfil; `DSConditionalSkeleton`                  |

- Os componentes são construídos a partir dos tokens e não leem o tema. Os tokens são tipos de valor
  `Sendable` simples.
- `ThemeManager` e `DSToastManager` são classes `@MainActor` `@Observable` com instâncias compartilhadas
  e inicializadores públicos, então podem ser injetadas (`DSThemeProvider(themeManager:)`,
  `DSToastContainer(manager:)`) e testadas.
- Os testes (`swift test`) usam Swift Testing: cálculos dos tokens, contraste, resolução de temas, fila e
  temporizadores dos toasts, funções auxiliares dos componentes, os trechos da documentação, impressões
  digitais de referência de cada grupo de componentes nos modos claro e escuro, e views hospedadas no
  AppKit para o provedor de tema, a cor da chave e o anel de foco do campo OTP. A CI também os executa em
  um simulador de iOS.

## Roteiro

- Criar a tag 2.0.0 e publicar as notas da versão a partir do [CHANGELOG.md](CHANGELOG.md).
- Fazer os componentes lerem o tema ativo, para que temas predefinidos e de marca também mudem o estilo
  deles.
- Elevar ao nível WCAG AA o contraste das iniciais dos avatares sobre as cores mais claras da paleta e o
  da marca de seleção da caixa de seleção no modo escuro.

Em junho de 2026 o pacote foi reduzido a arquivos provisórios; a 2.0 restaura os tokens, o mecanismo de
temas e os componentes anteriores, corrige os bugs encontrados no caminho e adiciona os testes. Os
componentes da API 1.x (alertas, modais, barra de navegação, barra de abas, gráficos) não foram
recuperados. Ideias e relatos de bugs são bem-vindos como
[issues](https://github.com/muhittincamdali/SwiftUI-Design-System-Pro/issues).
